# ADR 0019：显示器查询隔离与应用延迟上下文

状态：实施完成，本地整合验证通过，等待两平台CI构建。日期：2026-11-07。

## 原因

ICMP ping 不经过应用任务，不能代表 ScreenFerry 的心跳往返。客户端在发送 Ping 前取本机单调时刻，处理 Pong 时结束，期间包含两端程序等待、传输及处理。已有每秒显示器查询同步占用单线程 runtime；控制端原生查询变慢时，被控端可以同时出现低调度迟滞和高应用 RTT。

用未修改的 dc24529 引擎、独立双端 runtime、mock 平台和真实 localhost TCP/TLS 复现：控制端每次显示器查询人为延迟120ms时，客户端应用RTT最大122.209ms，客户端调度最大2.575ms，ICMP最大0.161ms。它证明结构机制，不证明实机Windows显示器API是全部尖峰的根因。本机观察与合成实验原始数据留在工作区诊断目录，不提交用户网络或操作数据。

## 决策

- 每个引擎持有一个串行显示器查询线程。启动与周期刷新均通过有界请求/结果通道；至多一项在飞，慢查询期间不补排周期任务。保留最近有效布局，查询失败或空结果不覆盖已有布局。
- 客户端新会话先丢弃旧会话在飞结果，再完成新鲜查询，之后才建立网络连接，不占用对端握手期限。无显示器仍可配对，有效范围在已信任输入握手前校验。线程与引擎绑定，旧引擎结果无通道进入新引擎；停止不join无法强制取消的原生调用。全进程最多32个查询线程，已进入系统调用的线程持有名额直至退出，避免连续重启无限遗留线程。
- 输入状态机维持现有顺序；不因周期查询等待系统驱动。显示器变化结果在核心线程原子地更新布局并通知对方，保留切屏/按键语义。
- 本机性能窗口新增 `display_query`、`cursor_switch`、`heartbeat_send`。显示器时长只测工作线程内原生查询，包含失败，不代表核心线程阻塞；光标切换测控制端grab/release及被控端显示/隐藏；心跳写入包含Ping和Pong的编码、写入、flush等待及发送错误，不表示对端已确认。
- 指标仍使用本机单调时钟，5秒窗口、近似分位数、精确max及>100ms计数。IPC3只做可缺省的字段扩展，不改变设备间线协议或配置schema。
- 诊断导出保留常规60秒/每来源12/全局128个窗口；另存最近4次>100ms上下文，每次最多前2、触发1、后2个窗口及触发阶段，重叠触发合并不延长容量。上下文可超过60秒保留，来源断线/重连及引擎换代清空对应记录。只写入完整导出文件，复制摘要只提供数量，State不附加历史；不记录按键、文字或坐标。不用两台设备的墙钟直接相减，不从单一阶段超过阈值自动推断原因。
- 总览和性能页称“应用往返”，区分最新采样平均与历史峰值；增加最新已结算样本的观测时间。缺少时间字段的旧后台显示未知，时间仅表示后台观测样本的时间，不是报文到达内核的时间。

## 范围与代价

本批不改变输入传输偏好、移动合并默认值、Wi-Fi/系统安全设置。Windows光标切换当前仍可能同步等待；本批测量它的耗时，不改变其确认/定位顺序。会话读写拆分、拖放剪贴板/metadata隔离、文件清理锁及位置积压策略保留到后续批次。

后台查询意味着显示器刚变化时仍短暂使用上一次有效布局；正常周期最多约1秒加查询时间，没有承诺原生API挂死时还能获知新布局。查询已开始后不能安全强杀；若名额用尽，新的启动异步等待，可取消。诊断只覆盖已完成调用，永久挂起不会产生完整耗时样本。

## 验证

新增回归使用真实TLS会话与受控平台接口，验证控制端/被控端查询阻塞超过1秒时心跳与按键释放仍有进展；在飞查询不补排、失败/空结果保留缓存、双向布局更新、启动取消不join、重连旧结果丢弃及旧查询阻塞时不提前建立连接。另验证两端心跳写入/光标切换统计、IPC缺省兼容、诊断容量与生命周期、实际导出及UI样本年龄。

相同120ms慢查询隔离实验，修复后18次客户端RTT最大0.394ms，>100ms为0；控制端调度最大2.167ms，客户端2.892ms。原生模拟慢查询实测120.192–125.038ms，共18次，确认负载仍存在。实验是debug构建、回环及mock平台，阶段窗口按采集时间近似判断；不作为发布版性能或真实Wi-Fi改善承诺。

完整工作区检查及两平台Actions结果见repair-validation.md最新记录。自动测试与回环实验不代替真实双机尾延迟验收，不声称本批消除所有100ms尖峰。
