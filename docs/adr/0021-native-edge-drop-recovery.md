# ADR 0021：首次拖放识别与原生接收区域

状态：实施完成，本地整合验证通过，等待两平台CI构建。日期：2026-11-07。

## 问题

用户反馈Mac向Windows、或双向拖文件偶尔无反应，重复数次才开始。默认使用场景仍为Mac mini Wi-Fi、Windows有线；临时直连仅用于延迟对照，不能要求用户长期使用直连。

第二批异步拖放读取存在可复现的识别竞态：按下时提交的Baseline查询可能在系统已更新拖放剪贴板之后执行，后续变化计数保持相同。Mac原实现没有watch_edge原生接收条，预览不出现便没有DragEntered来恢复识别。另有读取瞬时为空后缓存为空列表、停止整次拖动重试的问题。

两个平台还共享窗口交接风险：文件刚被识别便撤销接收条，胶囊下一帧才绘制；或鼠标钩子的Up先于原生Drop回调，窗口提前收起。旧收到文件卡片也可能占用共享窗口，使新拖动所在位置的接收条无法生效。

## 决策

- Mac实现watch_edge，接收条与胶囊共用NSPanel，背景低透明度但不把整个窗口alpha设为0，保持拖放命中及不抢焦点；场景/接收条状态独立保存，隐藏场景回退接收条，销毁同时清除。
- 近边缘的活动拖动始终保留接收条，即使预览已识别；胶囊覆盖接收条时不撤销原生窗口。未识别拖动需要接收条时暂时让旧卡片让出窗口，但不丢弃旧卡片数据。
- 原生DragEntered是当前拖放证据，可强制读取并建立尚未被指针状态处理的拖动；不依赖异步Baseline恰好先于系统更新。没有该证据时，仍不把未变化的旧拖放剪贴板当成新文件。
- 空读取按现有50ms有限节奏重试；一项查询在飞，结果仍绑定拖动代次，不因重试发出文件。
- 预览只读取文件名/项数，不遍历磁盘metadata；大小由真实传输清单准备后提供。慢磁盘不能阻止接收目标出现。
- 近边缘松开后保留目标与接收区域250ms等待原生Dropped，真正发送只使用Dropped携带的路径；没有原生Drop则自动收起，不发送缓存内容。暂停/断开/布局清空、新拖动和拖出自身卡片不能继承旧目标。
- 原生Dropped到达后立即显示准备提示并记录无路径/文件名的阶段日志，失败在本机显示原因。此日志用于区分系统没有投递Drop与后续文件准备/连接问题。

## 边界

不修改TCP/QUIC偏好、Wi-Fi或以太网配置，不将拖放启动问题归因于网络重传。没有修改设备线协议、配置schema或IPC版本。实际Drop回调携带路径是权威来源，不通过MouseUp猜测或自动发送旧文件。

自动回归覆盖真实TLS文件落盘及受控平台事件先后；Mac原生透明目标的拖入命中仍需安装后用户操作确认，不声称mock测试等同Finder/OLE原生验收。

新增8项回归覆盖基线晚于系统数据、瞬时空读取、原生进入早于指针状态、Up先于Drop、无Drop取消、旧卡片让出窗口与新位置首帧、多设备新手势不继承旧目标、断线重置后拒绝迟到Drop。拖放全套27通过；工作区默认485、全feature496通过，各3项既有环境依赖忽略；默认/全feature/Windows交叉Clippy、格式、结构lint及cargo-deny通过。
