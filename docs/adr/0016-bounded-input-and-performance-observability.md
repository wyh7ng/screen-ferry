# ADR 0016：输入背压、性能观测与后台工作预算

状态：已实施。日期：2026-11-06。

## 背景

首批已隔离同步剪贴板与磁盘操作，但捕获/发送积压、文件带宽竞争、日志整卷读取和全界面高频重建仍会拖慢响应。用户要求先完成开发，不继续组织人工验收。

## 决策

- 保留单线程输入状态机、默认 TCP+TLS。系统捕获回调使用有界通道 try_send，不等待网络或磁盘。溢出后终止该引擎并释放远端按键/鼠标，不能漏掉 KeyUp 后继续共享。
- 鼠标合并为显式可选项，默认关闭。只合并布局处理后的连续绝对移动，任何按键/鼠标按钮/滚轮/切屏和靠近边缘的路径都形成屏障；拖拽与按键保持期间不合并，不固定等待凑批次。
- 本机单调时钟统计捕获排队、发送排队、发送、接收注入、应用 RTT 与调度迟滞。每5秒输出固定大小直方图的近似P50/P95/P99及精确max/次数；不记录键值、文字或指针轨迹。捕获队列无法无锁取得当前最老事件年龄，oldest_us为null，另报已消费最大等待max_wait_us。
- 配置schema6迁移到7，新增file_rate_limit_mbps（十进制MB/s，0不限）和coalesce_motion（false）。UI、IPC、磁盘配置和运行中更新保持一致，保存失败保持旧设置。
- 所有文件发送共用可取消的 FIFO 内容字节预算队列，避免每个连接都取得完整限速。默认 0 不限速；在线更改影响等待中的额度，动态分块避免大幅降速后旧大分块长期占据队首。预算不包含协议开销，也不限制剪贴板、接收流量或其他进程；不自选强制限速，不承诺物理链路隔离或降低 Wi-Fi 输入延迟。
- 已完成回执按最近 7 天 / 1024 份保留策略清理，以先达到的保留边界为准；启动、完成后与每小时异步触发，非到期瞬间回收。清理排除活跃任务、partial 内容及未完成意图，不删除下载文件。原始 `partial/<id>/` 不自动认领，第一批设备隔离缓存与二元素完成回执仍可读取；回执回收或手工清缓存后不再承诺历史去重。
- 文件提交前持久化意图，名称碰撞和跨卷更新各项记录；跨卷复制先登记私有容器身份，复制校验完再记录目标卷来源并原子不覆盖改名。相同任务再次通告时核对稳定对象身份与内容摘要，认领已提交项；用户修改、替换或移动后无法可靠确认则保留并报冲突，不能覆盖、删除或另存第二份掩盖冲突。不是启动时自动提交所有缓存，也不持久化发送方的内存任务。
- Mac 尽可能同步目录，Windows 改名与记录替换请求 `WRITE_THROUGH` 并明确不支持目录 fsync。新意图缩小并支持恢复可识别的改名/回执间窗口，不宣称所有文件系统上具备跨目录掉电事务；多项提交后续失败保留已公开项并报告部分保存。去重回执继续使用协议 1 的 `FileResume(index=清单长度, offset=0)` 与 `FileDone`，未增加线上字段。
- 日志写入使用专用线程、有界队列和单事件64KiB上限；队列满只丢日志并报告数量，不阻塞输入。退出排空已接受的日志，最多等两秒，永久阻塞的设备仍可能丢失尾部日志。
- 日志读取使用不透明游标：已打开文件的稳定身份、字节offset、前一段摘要、累计完整行数。每页最多128KiB/1000行、首次仅尾部500行；换卷/截断重置，半行留到下次，超长行明确跳过。保留legacy offset接口；新界面用request_id与单请求在飞防乱序。lines_total为当前游标累计读取量，不伪称全卷总行数。
- 高频RTT、指标和文件进度按设备/任务合并未消费最新值；连接/终态是屏障，不能在Done后回放旧Running。每个占位有独立序号，旧占位不能拿走新代数据。
- 本机UI连接任务由JoinSet持有，最多32条；请求通道256条，慢客户端已有256条发送上限，断开后可重建状态。
- Flutter通过语义分域订阅缩小刷新范围；深层字段变化仍触发相关页面，时长显示由独立低频节拍更新。
- resident拆分命令、设置、后台任务、诊断和状态投影文件，继续封装在现有engine crate；不增加层间依赖。

## 边界

统计值不等于输入到画面呈现时间，两个设备单调时钟不能相减；合并与限速均不能保证消除Wi-Fi尖峰。QUIC实验另见ADR0017，默认传输不在本决策中变更。原生系统行为需后续验收，本轮不要求用户继续操作。
